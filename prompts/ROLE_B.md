# Стартовое задание для ИИ участника B

Ты работаешь в роли B проекта Datathon 26 ForteBank на втором ноутбуке RTX 4050. Сначала прочитай AGENTS.md, TEAM_WORKFLOW.md, FORTEBANK_PIPELINE.md и docs/CONTRACTS.md. Проверь существующий код, текущую ветку и документы передачи работы. Если есть docs/WORKER.md или docs/HANDOFF_A.md, прочитай их, чтобы использовать реальные структуры наблюдений A.

Твоя область: каталог типов событий, актуальные публичные нормы РК, условия применимости и исключения, app/rules/, config/rules.yaml и evaluation/. Данные каждого ролика остаются локально. Человек команды просматривает видео и проверяет спорную разметку; облачный помощник не получает кадры, описания сцен или локальные модельные отчёты. Для программной проверки используй синтетические наблюдения и агрегированные метрики.

Работай в feature/rules-eval. Сначала воспроизведи аудит по docs/DATA_SETUP.md, затем закрепи разделение по группам дубликатов и независимым сценам. Не используй имя или хеш ролика для предсказания метки. Не меняй отложенную выборку после просмотра ошибок без отметки об утрате независимости.

Проверь текущие нормативные тексты, не считай номера из первоначальной публикации автоматически действующими. Реализуй проверяемые правила над наблюдениями, с исключениями, без генерации ссылок моделью. Отделяй гипотезы правил от подтверждённых правил. Отсутствие наблюдения не доказывает отсутствие обязательного действия.

Сначала передай A и C формат правила и работающий оценщик на синтетических случаях; затем добавляй проверенные классы. Дообучение и замена базовой модели не нужны без измеренного основания. После проверки закоммить и запушь свою ветку. В docs/HANDOFF_B.md укажи реализованное покрытие, проверки, ограничения и требования к стыкам без конкретных банковских сцен.

## Постоянное правило обновления промпта

По прямому указанию пользователя после каждого завершённого этапа работы по роли B обновляй этот файл локально до финального ответа. Сохраняй основные инструкции роли, а раздел текущего состояния переписывай по фактическому результату: что сделано, какие проверки выполнены, что осталось, какие есть блокеры и следующий шаг. Обновляй также docs/HANDOFF_B.md, если изменились реализованное покрытие или условия интеграции. Не включай банковские сцены, конкретные аннотации, секреты или модельные отчёты. Для справочных ответов без изменений состояния проекта повторная запись не требуется.
