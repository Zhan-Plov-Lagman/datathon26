## Происхождение фактов

`finalize_bundle(..., local_context=None)` теперь требует для каждого пакета уникальную запись diagnostics.episodes с теми же rule_id/event_id и fact_sources. Bool имеет происхождение visual, local_context или mixed. Визуальные ссылки разрешаются в выходном report и входят в observation_refs соответствующего пакета. Для mixed/local_context нужен переданный отдельно локальный контекст: A validate_context проверяет job/display, C сопоставляет view_id/context_version/basis_ref/reviewer. Нельзя считать присланный самим пакетом context_ref независимым подтверждением.

Null сохраняется с origin=unknown и непустой причиной. Явные conflicts эпизода исключают поддержку: в отдельной копии факты этого пакета становятся unknown, к внутреннему unresolved добавляются исходные причины. Исходные facts/диагностика не меняются. Неправильные ссылки или происхождение — нарушенный технический контракт; явно заявленная неизвестность/конфликт — данные для политики B.

Это структурная проверка прослеживаемости, не подтверждение истинности наблюдения, геометрии или нормы. Их качество проверяют A/B локально. Визуальные описания не разбираются по ключевым словам и не становятся фактами.

## Интерфейс evaluator

```python
evaluator = DetectionEvaluator(
    registry=reviewed_registry,
    release=validated_release,
    context_provider=None,
)
# Интерфейс существующего IntegratedProcessor:
decision = evaluator.evaluate(report, video_path=path, worker=worker, deadline=deadline)
```

validated_release задаётся после реальной локальной приёмки. Поля:

- validation_reference — ссылка/идентификатор локального отчёта приёмки, без содержимого сцен;
- registry_sha256 — SHA-256 сериализованного реестра по алгоритму B (registry_digest);
- model_id/model_revision — принятые версии модели;
- detector_versions — непустой словарь rule_id → принятая версия детектора;
- policy_version — detection-policy.v1.

Все настроенные классы должны быть reviewed и validated_on_local_cases=true. Конструктор проверяет реестр/политику и копирует конфигурацию. evaluate проверяет модель, передаёт одному существующему worker.assess оставшийся бюджет с резервом 5 секунд на правила/JPEG, исходный абсолютный deadline и копию контекста. Затем проверяет bundle, запускает B и сверяет версии исполненных детекторов. Резерв не гарантирует время JPEG; внешний deadline продолжает действовать.

Строка validation_reference и флаги реестра не являются автоматическим доказательством качества. Их нельзя заполнять фиктивно, чтобы включить readiness. Тесты используют явно синтетический релиз и reviewed-реестр только в памяти. Никакого универсального factory, создающего такой релиз, нет.

context_provider, если нужен после согласования, получает копию отчёта и возвращает локальный контекст применимого job/display. Он не должен подставлять метки по имени/хешу или требовать ручной разметки каждого загруженного видео. По умолчанию контекста нет.

Поддержанное событие получает тип и нормативное обоснование из результата B, визуальное описание из связанного наблюдения, покрывающего anchor. Структурированные feature_key-наблюдения не подставляются как пользовательское описание. Источник JPEG — существующий worker.evidence, один пакет запросов. IntegratedProcessor дополнительно проверяет совпадение возвращённых PTS с запрошенными исходными PTS, помимо декодирования JPEG и диапазонов времени. Код не может доказать происхождение произвольных JPEG без доверенного worker; это проверяется полным локальным прогоном.

RuleDecision возвращается с rules_version и negative_policy_version B. Неизвестность после работающего поиска подчиняется принятой политике «не обнаружено». В публичном JSON остаются только поля ТЗ; локальная диагностика/версии не публикуются.
