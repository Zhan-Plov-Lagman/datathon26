# Один ноутбук A, без VPN

Выбрано пользователем C 18 октября 2026: API, SQLite, интерфейс и один GPU worker работают на A. Публичный адрес отложен отдельным ответом пользователя. C продолжает разработку и интеграцию. Команды ниже подготовлены; на настоящем ноутбуке A они ещё не выполнены.

## Подготовить отдельный checkout, сохранив работу A

В PowerShell из существующего репозитория A, где уже есть рабочие `.venv` и локальные веса:

```powershell
git status --short
git fetch origin
$gpuPython = (Resolve-Path .\.venv\Scripts\python.exe).Path
$gpuModel = (Resolve-Path .\models\Qwen3-VL-2B-Instruct-shards).Path
git worktree add --detach ..\datathon26-run origin/feature/api-ui
Set-Location ..\datathon26-run
& $gpuPython -m pip install -r requirements-api.txt
& $gpuPython -m scripts.setup_coordinator
```

Если `datathon26-run` уже существует, не удалять и не перезаписывать: выбрать новое имя. Worktree сохраняет незавершённую работу A на исходной ветке. Среда и веса используются по абсолютным путям; повторно скачивать модель и создавать среду не требуется. Зависимости API устанавливаются в существующую среду A; после установки выполнить `& $gpuPython -m pip check`. GPU-совместимость на Python 3.12 проверяет A по `WORKER.md`.

В созданном локальном `.env` настроить без публикации значений:

- `FORTE_API_KEY` и `FORTE_WORKER_KEY`: генератор создаёт разные случайные ключи. Не подставлять рабочие ключи из чата; ключ работника остаётся на том же ноутбуке.
- `FORTE_MODEL_DIR`: абсолютный путь из `$gpuModel`.
- `FORTE_RULES_FACTORY`: настоящий модуль и фабрика проверенного evaluator B. **Их пока нет.** Нельзя указывать `app.rules:evaluate` (это функция другой формы) или фабрику из `tests`.
- `FORTE_STORAGE`: при необходимости отдельный локальный каталог вне OneDrive; иначе используется `%LOCALAPPDATA%/Datathon26/runtime`.

Текущий обязательный блокер A/B описан в `INTEGRATION_C.md`. Наличие нормативной ссылки и команды запуска не означает готовность анализа.

## Запуск

После готовности evaluator, модели и локального `.env`:

```powershell
& $gpuPython -m scripts.run_local
```

Либо первичная установка и запуск одной командой из подготовленного worktree:

```powershell
.\start.ps1 -WithWorker -Python $gpuPython
```

Открыть `http://127.0.0.1:8000`, вставить локальный `FORTE_API_KEY`, нажать «Проверить подключение». Оба API слушают только loopback; worker явно обращается к `http://127.0.0.1:8001`. VPN, firewall rule и открытие 8001 наружу не нужны. При занятом порте команда откажется запускать вторую копию. При завершении одного сервиса supervisor останавливает другой; Ctrl+C останавливает оба вместе с GPU-процессом. При отсутствии фабрики запуск блокируется до загрузки модели.

Для осмотра только интерфейса без модели использовать `& $gpuPython -m app.api` или `.\start.ps1 -Python $gpuPython`. Готовность анализа останется false без настоящего обработчика. Проверить существующие процессы до запуска; не останавливать работающие задания ради второго экземпляра.

## Проверка и передача результата C

В отдельном PowerShell из того же checkout задать `$gpuPython` заново абсолютным путём к среде A:

```powershell
& $gpuPython -m scripts.check_api http://127.0.0.1:8000
& $gpuPython -m scripts.check_e2e http://127.0.0.1:8000 '<локальный путь к проверочному MOV>'
```

Первый инструмент делает шесть проверок доступа при наличии ключа. Второй требует настоящую готовность, загружает MOV под нейтральным именем, опрашивает статус и проверяет точную публичную форму, соответствие job_id, вердикта/списка событий, таймкоды и декодирование JPEG. Общий бюджет проверки — 300 с, включая загрузку и ожидание; внутренний бюджет сервера по умолчанию — 240 с. Отсутствие готовности не создаёт задание. Сбой/невалидный результат даёт ненулевой код выхода.

В выводе только `completed`, общее время, количество событий/проверенных JPEG либо фиксированный код ошибки. Видео, кадры, описания, ответы модели, ключи, имена файлов и job_id не печатаются. Результат осматривает человек команды локально. Число событий и успешное декодирование сами по себе не доказывают правильность распознавания/юридического вывода. Для C достаточно технических показателей и агрегатов.

## Статус сдачи

- Синтетический путь через реальные HTTP-серверы и отдельный тестовый процесс проверен на C.
- Настоящая модель, факты и правила вместе через API не проверены.
- Публичный HTTPS и проверка из другой сети отложены пользователем. Localhost доступен только на A и не заменяет публичный API из ТЗ.
- Второй GPU подключать только после успешного настоящего одиночного сценария.
