## Режим и ограничения

Фабрика `app.jobs.unified:create_signs_processor`, политика `signs-targeted.v1`.
Это поиск признаков возможных нарушений, не окончательное правовое заключение.
Ровно два класса: `cashier_leaves_service`, `personal_items_storage`.
Источник текста проверен; реестр не изменён на reviewed и остаётся
`hypothesis`, `validated_on_local_cases=false`. Точность — `unmeasured`.
Подробные критерии: [SIGNS_POLICY.md](SIGNS_POLICY.md).

`no_violation` означает отсутствие квалифицировавшихся признаков в завершённом
поиске; неизвестные факты не заменяются false. Неполный проход, ошибка модели,
декодера или дедлайн должны завершаться `failed`. Исходные данные, ответы модели
и сцены остаются внутри команды; здесь публикуются только технические агрегаты.

## Жизненный цикл GPU и supervisor

Фактически проверен daemon с `InprocClient` / `UniProcExecutor`,
`VLLM_ENABLE_V1_MULTIPROCESSING=0`. Первая загрузка: 168,237 с; весь bootstrap
вместе с синтетической генерацией: 174,875 с. После закрытия GPU полностью
освобождён. Повторная загрузка: 61,013 с. При принудительном дедлайне 1 с
остановка заняла 1,634 с; процессов-сирот не осталось.

Реальный серверный daemon запущен вручную через `setsid`/`nohup`.
Для supervisor проверены `bash -n` и отказ при уже существующем API или worker
с exit 1. Полный startup/signal lifecycle supervisor **не проверен**; эти
частичные проверки не заменяют его. Время холодного старта не включается в
7,122 с измеренного задания после готовности worker.

## Что не подтверждено этими проверками

Положительное событие и его JPEG через публичный API на реальном видео пока
не наблюдались. Не заявляются независимые precision/recall, p95 или подтверждённая
устойчивость длительной нагрузки. Техническое восстановление после одной ошибки
не заменяет длительный тест стабильности.
