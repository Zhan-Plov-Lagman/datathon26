## Что работает

- FastAPI POST `/api/v1/analyze`, GET `/api/v1/jobs/{job_id}`, точные поля ТЗ, проверка `X-API-Key` до чтения загрузки.
- Сохранение исходника с `fsync` и SQLite до 202; случайные имена; лимит размера, ограничение очереди, отсутствие путей/traceback в публичных ошибках.
- SQLite WAL, атомарная выдача, аренда/heartbeat, общий дедлайн, максимум две попытки, отклонение устаревшего ответа. Статусы и результат переживают перезапуск.
- Отдельный закрытый сервер на 8001 с `X-Worker-Key`; его маршрутов нет на публичном 8000. Никакого общего SQLite-файла между ноутбуками.
- Клиент GPU: передача исходных байтов, один процесс модели между успешными заданиями, heartbeat, принудительное завершение зависшей обработки, пересоздание процесса после ошибки.
- Адаптер к A `LocalGPUWorker`; один дедлайн обзора/уточнения/доказательств; JPEG всех событий извлекаются одним проходом. Стык B предложен в `WORKER_TRANSPORT.md`, его ещё нужно подтвердить.
- Проверка внутреннего результата: законченный анализ всего видео, отметка проверки правил, версии, согласованность вердикта, таймкоды, 1–3 реально декодируемых JPEG на событие. Наблюдения без правил не принимаются как результат. Для пустого списка событий теперь обязательна `negative_policy_version`: версия проверенной B политики отрицательного решения. Публичная схема не меняется; реальные правила/политика этим полем не подменяются.
- Русский интерфейс без внешних ресурсов: MOV, готовность, статус, события, исходные JPEG, переход к времени локального видео, восстановление последнего ID. Ключ не сохраняется в браузере.
- `.env.example`, генерация двух ключей, `start.ps1`, закреплённые лёгкие зависимости, пример публичного HTTPS через Caddy, скрипт проверки доступа.

## Запуск и продолжение

На C: `.\start.ps1` из корня, либо после установки `.\.venv\Scripts\python.exe -m app.api`. UI — **http://127.0.0.1:8000**. Ключ находится в локальном `.env`; в Git его нет. Хранилище по умолчанию — `%LOCALAPPDATA%/Datathon26/runtime`, вне OneDrive. Полная инструкция — [DEPLOYMENT.md](DEPLOYMENT.md).

Для подключения A запустить C с `--worker-host <private-IP-C>`. На A установить `requirements-api.txt` поверх его worker-среды, задать локально `FORTE_WORKER_KEY`, `FORTE_COORDINATOR`, `FORTE_MODEL_DIR`, `FORTE_RULES_FACTORY`, затем `python -m app.jobs.worker --worker-id gpu-a`. Протокол и фабрика B — [WORKER_TRANSPORT.md](WORKER_TRANSPORT.md).
