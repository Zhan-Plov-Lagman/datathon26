Актуальная схема: браузер на A → `http://127.0.0.1:8000` → SQLite → GPU worker на A через `http://127.0.0.1:8001`. Оба порта слушают loopback. Связь C/A, VPN, открытие firewall и проброс worker-порта не требуются. C разрабатывает код; запуск — `SINGLE_LAPTOP.md`.

На C существующий UI/API доступен по localhost и прошёл 6/6 HTTP-проверок. На A новая общая команда ещё не запускалась. Синтетический HTTP-путь проверен на C в отдельном тестовом окружении; настоящий анализ не подтверждён.

## Публичный адрес — отложенный этап

Публичный HTTPS пока не создан, доступа из другой сети не проверяли. Публичность API обязательна по исходному кейсу; локальный запуск её не заменяет. Позже публиковать только 8000, никогда 8001 и не каталоги с `.env`, видео или результатами. Ключ жюри передавать отдельно от Git.

Для транспорта исследован ngrok. Обычный HTTPS endpoint завершает TLS в облаке ngrok; сквозное шифрование требует отдельного TLS endpoint с завершением на устройстве команды и доверенным сертификатом. По текущим документам ngrok TLS endpoints отсутствуют на бесплатном плане. Пример с самоподписанным сертификатом не подходит для обычного браузера жюри без отдельного доверия.

Источники: [где завершается TLS](https://ngrok.com/docs/gateway/domains/tls-termination), [завершение на локальном агенте](https://ngrok.com/docs/gateway/agent/agent-tls-termination), [бесплатный план](https://ngrok.com/docs/pricing-limits/free-plan-limits).

Ничего не покупалось, аккаунты и туннели не создавались. Передача банковских видео через внешний туннель не выполнялась. Caddy из `deploy/Caddyfile` остаётся вариантом при появлении домена и публичного маршрута; сейчас их нет.

После настройки реального HTTPS выполнить из другой сети:

```powershell
python -m scripts.check_api https://<адрес-команды>
python -m scripts.check_e2e https://<адрес-команды> '<локальный MOV>'
```

Ключ — только в локальном `.env`/переменной окружения, не в URL. Сначала 6/6 проверок доступа, затем готовность и полный путь. Содержимое проверяет команда локально; помощнику передавать только технические показатели и агрегаты. `/internal/jobs/claim` на публичном адресе должен вернуть 404.
