# Подключение A и C из разных сетей

Состояние 17 октября: общей LAN, своего домена и публичного сервера нет. Tailscale на C пока не установлен, настоящий адрес не получен. Ниже подготовленные команды; подключение и проверка через интернет ещё не выполнены.

Схема: A → закрытая сеть Tailscale → C:8001; жюри → HTTPS Funnel → C:127.0.0.1:8000. Обработка видео остаётся на ноутбуках. Tailscale Funnel завершает TLS на устройстве C, выдаёт адрес в домене `*.ts.net` и имеет ограничения пропускной способности. Поэтому полное время загрузки и обработки нужно измерить на настоящем подключении. [Документация Funnel](https://tailscale.com/docs/features/tailscale-funnel), [CLI и TLS](https://tailscale.com/docs/reference/tailscale-cli/funnel).

## 1. Подключить ноутбуки

Установить [Tailscale для Windows](https://tailscale.com/download/windows) на C и A. Владелец входит в аккаунт, приглашает участника A в ту же сеть; пароли и auth keys не передавать в чат помощника. Не создавать exit node и не включать маршрутизацию всей LAN.

В PowerShell на каждом ноутбуке:

```powershell
$ts = 'C:\Program Files\Tailscale\tailscale.exe'
& $ts ip -4
```

Записать адреса C и A вида `100.x.x.x`. На A проверить `& $ts ping <IP-C>`. Это проверка VPN, ещё не готовности API. В политике сети разрешить A доступ только к C TCP 8001; если ранее есть широкое разрешение, одно добавление узкого правила его не отменит. Не подключать к этой сети посторонние устройства.

## 2. Запустить закрытый API на C

Перед перезапуском проверить текущий процесс и отсутствие выполняющихся заданий. Остановить прежний экземпляр штатно, затем из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m app.api --worker-host <IP-C>
```

Публичное приложение остаётся на `127.0.0.1:8000`; обработчики доступны на Tailscale IP C:8001. Не использовать `0.0.0.0` и проброс 8001 через роутер/Funnel. Если Windows Firewall блокирует соединение, на C из PowerShell администратора добавить точное разрешение после подстановки адресов:

```powershell
New-NetFirewallRule -DisplayName 'Datathon26 worker from A' -Direction Inbound -Action Allow -Protocol TCP -LocalAddress <IP-C> -LocalPort 8001 -RemoteAddress <IP-A> -Profile Any
```

На A: `Test-NetConnection <IP-C> -Port 8001`. Ключ `FORTE_WORKER_KEY` передать A отдельно защищённым каналом, сохранить локально. Настроить `FORTE_COORDINATOR=http://<IP-C>:8001`; HTTP здесь идёт внутри зашифрованной VPN. Остальные переменные и запуск — `WORKER_TRANSPORT.md`. Реальный GPU worker запускать после готовности модели и evaluator B; синтетический не регистрировать в рабочем сервисе.

## 3. Выдать публичный HTTPS-адрес

На C сначала проверить локальный API, затем включить Funnel только для 8000:

```powershell
.\.venv\Scripts\python.exe -m scripts.check_api http://127.0.0.1:8000
& $ts funnel --bg --https=443 http://127.0.0.1:8000
& $ts funnel status
```

При первом включении владелец проходит предложенное Tailscale подтверждение в браузере; потребуются MagicDNS, HTTPS и разрешение Funnel в сети. Записать выданный URL `https://<имя-C>.<сеть>.ts.net`. Не передавать Funnel путь к каталогу или `.env`. На Windows для сохранения VPN после выхода пользователя можно включить Run Unattended в Tailscale; сам API также должен оставаться запущенным, а ноутбук — включённым. [Режим Windows](https://tailscale.com/docs/how-to/run-unattended).

Выключение именно этого HTTPS-входа:

```powershell
& $ts funnel --https=443 off
```

## 4. Приёмка из другой сети

На отдельном устройстве/мобильном интернете выполнить `python -m scripts.check_api https://<выданный-адрес>` из окружения с httpx/python-dotenv. Для шестой проверки ключ должен быть в локальной переменной `FORTE_API_KEY` или `.env`, без вывода в консоль. Ожидать 6/6 PASS; без ключа выполняются только пять проверок. Порт 8001 не должен публиковаться, `/internal/jobs/claim` на публичном URL должен вернуть 404.

Затем только команда локально проводит настоящий MOV через готовые A/B: измеряет загрузку, очередь, анализ и получение ответа суммарно; проверяет JPEG, таймкоды и вердикт. В чат помощнику передать только технические показатели. Успешная HTTP-проверка не подтверждает готовность распознавания. После успешного одного GPU подключить второй с отдельным ID и проверить две задачи и отказ.
