# Быстрая проверка по существующим заметкам

Новая утилита не требует переписывать B isa.txt. Она локально группирует заметки по видео, исключает точные копии и предлагает два примера для разработки. Ключевые слова применяются только для навигации по заметкам, никогда для предсказаний или ground truth. Имя файла служит соединению с исходником, хеш — устранению точных дубликатов.

```powershell
python -m evaluation.note_review --notes "B isa.txt" --video-dir "<папка MOV>" --output artifacts/departure-review
```

Открыть artifacts/departure-review/review.html обычным браузером локально. Там исходные ролики, существующие заметки, ответы Да/Нет/Неясно и кнопка сохранения reviewed-cases.json. Если браузер не воспроизводит MOV, открыть указанный на странице исходник в локальном плеере. Данные никуда не отправляются, сетевые обращения страницы запрещены CSP. Помощнику страницу/скриншоты не показывать.

Ответ относится именно к cashier_leaves_service: уходу за подтверждённую границу во время явно незавершённой передачи наличных. Предложенный сравнительный пример ещё не подтверждённый hard negative. Нельзя выдавать отсутствие ключевых слов за отсутствие события. Все записи изначально label=null/reviewed=false. Для неизвестного случая оценка точности блокируется; это не отрицательная метка.

После просмотра сохранить JSON в локальный artifacts и импортировать:

```powershell
python -m evaluation.note_review --reviewed-input artifacts/reviewed-cases.json --output artifacts/reviewed-records.json
```

Импорт проверяет имя проверявшего, бинарную метку, событие/время, целостность исходника и отсутствие точных копий. Файл records совместим с существующим evaluation score. Использовать только реальные выходы конечного детектора; candidate/receipt сами по себе не являются прогнозом публичного вердикта. Эту пару считать development, не независимой валидацией: выбор выполнен по заметкам до проверки модели. Полученные на ней показатели не оценка всего набора.

Утилита не создаёт local_context, не переносит метки в inference, не активирует реестр. Рабочая зона и визуальные критерии остаются отдельной проверкой. Прогон модели на выбранных путях может идти до человеческой проверки, но имеет только технические метрики.

# Локальная разметка и оценка B

Все команды запускать из корня проекта. Исходные аннотации сохраняются неизменными. Выходы допускаются только в исключённых из Git `data`, `artifacts`, `results`; файлы не перезаписываются.

```powershell
python -m evaluation prepare --input artifacts/dataset_audit.generated.json --output data/annotations.json
```

Человек локально открывает `data/annotations.json` и видео. Заполняет `scene_group` (одна постановка/ракурс/повторные съёмки — одна группа), бинарный `label`, `reviewed`, `events`, `hard_negative_tags`. У событий нужны `type` и `timecode_sec`; дополнительно сохранять начало/конец, роли, исключения, видимость и пояснения. Пустой таймкод отрицательного примера не заменять нулём. `ambiguous` снимается только после совместного разрешения противоречий. Точные дубликаты с разными исходными метками/временами автоматически отмечаются неоднозначными; обе исходные строки остаются.

После проверки групп выставить верхний `scene_grouping_reviewed: true`. Разделение блокируется без групп и бинарных меток. Оно объединяет транзитивно совпадающие хеши и сцены, приблизительно балансирует метки в пропорции 60/20/20 по уникальным хешам. Группы не разрезаются ради точного размера. Реального разделения до человеческой проверки сцен нет.

```powershell
python -m evaluation split --input data/annotations.json --output data/splits.json
python -m evaluation select --input data/annotations.json --splits data/splits.json --partition development --output data/eval-development.json
python -m evaluation score --input data/eval-development.json --predictions results/predictions.json --output artifacts/metrics-baseline.json
```

`select` оставляет одного представителя каждого точного хеша, проверяет неизменность манифеста SHA-256 и отмечает конфликтующие события дубликатов. `id` в оценке — имя представителя исключительно для соединения с результатом. Не импортировать `evaluation` в inference и не передавать метки модели. При изменении манифеста после фиксации создать новую версию разделения с записью причины и утраты независимости, если holdout уже изучен.

Предсказания — `{"predictions": [...]}`. Каждая запись: `id`, `status: done|failed`, `latency_sec` от приёма до готовности; для done также `verdict` и `violations` с `type`, `timecode_sec`. Получать их из настоящих результатов пайплайна, не из таблицы организаторов. Конкретные результаты хранить локально; CLI печатает только факт сохранения.

Метрики: TP/TN/FP/FN, precision/recall/F1 по успешно завершённым неоднозначностью не затронутым видео; отдельно missing/failed/ambiguous и completion rate. Не скрывать completion rate при публикации F1. Неуспешные положительные видео входят в пропуски событий. События сопоставляются один-к-одному максимальным паросочетанием в пределах 5 секунд и одинакового типа; повторное обнаружение считается FP. Отдельно типизация на временных совпадениях, MAE по типизированным совпадениям, попадания в 1/2/5 секунд, p95 (nearest rank), максимум и превышения 300 секунд. При неоднозначном совпадении нескольких событий выбор детерминирован, но не гарантирует минимальную суммарную временную ошибку. Допуски внутренние, не формула жюри. Undefined-метрика записывается `null`, а не 0/100%.

Журнал эксперимента хранить в `artifacts`: ревизия кода/модели, параметры квантования, sampling, prompt, SHA реестра/разделения, изменённый единственный фактор, размер выборки, полное время и ограничения. Проверять отдельными локальными срезами допустимые передачи, уход после завершения, перекрытые руки, обрезанное начало, несколько событий, быстрые действия, исключения и новый реальный ракурс. Подлинность JPEG и смысл доказательства оцениваются локально человеком/A; эти числа оценщик автоматически не придумывает.
