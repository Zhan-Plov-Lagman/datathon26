## Реализовано

- FastAPI: MOV multipart file, X-API-Key, POST analyze с 202 после сохранения, GET job по схеме жюри, readiness, ограничения размера/очереди и безопасные ошибки.
- SQLite: сохранение после перезапуска, атомарная аренда, heartbeat, ограниченные повторы, общий дедлайн и защита от поздних результатов.
- Отдельный private API на 8001, постоянный процесс модели, внешнее завершение зависшего процесса.
- Русский UI: загрузка, готовность, статусы, события/JPEG/переход по времени, восстановление задания, desktop/mobile; без внешних ресурсов.
- scripts.run_local и start.ps1 -WithWorker: один ноутбук, проверки конфигурации/портов, общий жизненный цикл API/worker. scripts.check_api/check_e2e: HTTP и полный контракт результата с выводом только технических агрегатов.
- finalize_bundle: идентичность отчёта/окна/квитанция, provenance, отдельный проверяемый local_context, конфликты без мутации исходных фактов. DetectionEvaluator: закреплённые версии принятого релиза, assess и B, RuleDecision; IntegratedProcessor: JPEG и точное соответствие запрошенным исходным PTS. Интерфейс — [EVALUATOR_C.md](EVALUATOR_C.md).

## Готовность и ограничения

Настоящий реестр B остаётся hypothesis/validated_on_local_cases=false. Приёмка детектора/контекста/качества, конфигурация ValidatedRelease и production-фабрика отсутствуют. Нельзя включать readiness по успешной квитанции, тестовому reviewed-реестру или фиктивному validation_reference.

B сообщает локальную подборку data/human-notes/review-pair-b в своей среде. Это кандидаты разработки из заметок, не проверенная разметка. C их содержимое не читал. Ветка feature/rules-eval-a-support содержит отдельную помощь A участнику B; C её не объединял вместо основной ветки B.

A сообщает раздельные замеры второго примера: analyze 27.687 с и assess+JPEG 230.828 с, сумма 258.515 с. Она превышает текущий бюджет C 240 с; это не единый API-прогон. Требуется реальное измерение полного пути и устранение превышения, с учётом лимита ТЗ 300 с и загрузки/очереди. Лимиты в этом этапе не менялись.

Полный банковский API-прогон, качество, общий latency, публичный URL/внешний доступ и второй GPU не подтверждены.
