# Передача результата роли A

Дата: 17 октября 2026. Участник: Арман, RTX 4050 Laptop 6 ГБ. Ветка: `feature/ml-worker` в https://github.com/Zhan-Plov-Lagman/datathon26.

**Что готово.** Локальное чтение MOV, выбор кадров по реальному PTS, окна с перекрытием, Qwen3-VL-2B-Instruct в NF4, проверка структурированного ответа, уточнение заданного интервала и извлечение 1–3 JPEG исходного разрешения. Модель загружается один раз и переиспользуется между заданиями. Сбой формата, декодирования или дедлайн не превращается в отрицательный вердикт.

**Что проверено.** Все 9 тестов `python -m unittest discover -s tests/worker -v` прошли. Среди них VFR-таймкоды, поворот видео, JPEG, границы интервалов, ошибочные ответы и сохранение смешанных типов весов при разбиении safetensors. `pip check` не выявил несовместимых зависимостей.

Синтетический GPU-прогон: видео 3 секунды, 4 кадра, одно окно; загрузка модели 18,343 с, анализ 4,938 с, включая декодирование 1,094 с. Пиковая выделенная память PyTorch — 1926 МиБ, зарезервированная — 2030 МиБ. Эти величины не включают память других приложений и не доказывают качество на банковских сценах.

Технический прогон двух реальных роликов выбран по длительности, без использования разметки. Настройки: окна 12 с, перекрытие 2 с, 6 кадров на окно, длинная сторона до 560 px, максимум 384 новых токена. Оба ролика обработаны полностью в смысле всех запланированных окон; дополнительно проверено извлечение последнего исходного JPEG.

Модель уже была загружена при старте измерения каждого ролика; в памяти между заданиями сохранялся один экземпляр. Пики памяти накопительные для процесса. Это один прогон, а не p95 и не измерение публичного сервиса: здесь нет очереди, правил B, автоматических уточнений и сетевой выдачи. Точность описаний и нарушений ещё не оценена. Подробные ответы сохранены только локально в `artifacts/benchmark-run1`; облачному помощнику передавались лишь технические метрики.

**Воспроизводимость.** Python 3.12.14; torch 2.8.0+cu128; torchvision 0.23.0+cu128; transformers 4.57.6; accelerate 1.12.0; bitsandbytes 0.48.2; av 16.1.0; Pillow 12.1.0. Остальные основные зависимости закреплены в `requirements-worker.txt`. Ревизия Qwen: `89644892e4d85e24eaac8bacfd4f463576704203`. Используются SDPA, float16 вычисления и NF4 с double quantization; дополнительного обучения нет.

На Windows единый файл весов не загрузился из-за error 1455. Рабочий вариант — восемь частей в `models/Qwen3-VL-2B-Instruct-shards`; монолитная копия удалена для освобождения места. Подготовка и запуск описаны в [WORKER.md](WORKER.md). На этой машине повторно скачивать или разбивать модель не требуется. В Git нет весов, среды Python или банковских данных.

**Стык B.** `LocalVideoAnalyzer.analyze` возвращает `observations.v1`, `analysis_kind: observations_only`. Получать `windows`, `operation_context`, наблюдения и ограничения обзора. Времена наблюдений вычислены из индексов кадров. Свободный текст модели — визуальная гипотеза, не доказательство применимости правовой нормы. Нужны проверенные правила, исключения, дедупликация событий и оценка качества на независимых сценах. Описание схемы — `docs/CONTRACTS.md`.

**Стык C.** Создать `QwenObserver` и `LocalVideoAnalyzer` при старте GPU-процесса, передавать последовательные задания. Не создавать модель на каждом HTTP-запросе и не запускать конкурентные генерации на одном GPU. После правил B извлечь доказательства через `extract_evidence`; C формирует публичный контракт. Общий бюджет включает очередь, анализ, уточнения и выдачу; кооперативный дедлайн внутри модели не заменяет внешний контроль процесса.

**Что ещё требуется.** Автоматическое уточнение по кандидатам B, нормативный вердикт, транспорт задач, API и очередь не реализованы в этой ветке. Пустые наблюдения не означают `no_violation`. Редкая обзорная выборка может пропустить быстрые действия. Нужны человеческая оценка качества, согласование B/C и сквозной прогон публичного сервиса.

**Ближайшие действия команды.** B начинает `prompts/ROLE_B.md`; C — `prompts/ROLE_C.md`. Оба читают этот документ и `docs/WORKER.md` из ветки A. C получает ветку командой `git fetch origin` и объединяет её после проверки интерфейсов. A продолжает локальные измерения и помогает уточнять события, не дублируя работу B/C.
