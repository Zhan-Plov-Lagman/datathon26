# Локальная проверка первого класса

Статус 18.10.2026: **не выполнена**. Пользователь подтвердил отсутствие совместной проверки. Ни источник нормы, ни синтетические тесты, ни наличие notes.md не заменяют её.

Проверяется физический уход `cashier_leaves_service`, а не смена внимания. Если в данных нет понятного положительного случая, так и фиксируем: пригодность этого класса для первой версии не подтверждена. Не подбирать трактовку под желаемый ответ.

## Порядок для B и A

1. B просматривает исходные видео локальным плеером, используя свои notes.md как указатель. Подбирает положительные, сложные отрицательные и неоднозначные случаи. Метка организаторов «нарушение» не является готовой меткой класса ухода.
2. Для каждого случая заполняет `data/human-notes/departure-validation.md`. Файлы, время, описания, кадры, основания фактов остаются только локально. A независимо проверяет спорные факты; несогласие сохраняется как unknown до разрешения.
3. Сложные отрицательные проверки: движение внутри зоны; смена внимания без ухода; подтверждённое завершение до ухода; другая установленная роль/операция. Неоднозначные: перекрытие, граница вне кадра, непонятное завершение/роль/операция, обрезанный эпизод. Это план категорий, не утверждение об их наличии в наборе. Отмечать отсутствующие категории.
4. До подбора параметров объединить точные копии и независимые сцены, зафиксировать development/tuning/holdout. Заметки, использованные при выборе класса/критериев, считать материалом разработки; не объявлять их независимой проверкой. Конфликтующие аннотации копий сохранить. Unknown не переводить в false ради существующего бинарного формата оценки.
5. A запускает реальный извлекатель фактов и уточнение с фиксированными версиями на локальных примерах, без доступа к меткам. Сохраняет пакеты и исходные доказательства локально. B сравнивает результат с человеческими фактами/эпизодами; ошибки разбирают вместе, после изменений повторяют проверку на независимой части.
6. В общий Git публикуются только агрегаты, версии и ограничения. Данные и отчёты со сценами не выводятся в облачный помощник. Никакой проверки в этом документе нельзя считать выполненной заранее.

## Что измерить и зафиксировать

- Число независимых положительных, сложных отрицательных, неоднозначных случаев и сцен; сколько категорий отсутствует. Точные копии не увеличивают объём доказательств.
- По каждому факту: число истинных/ложных/неизвестных человеческих значений, ошибок извлечения, конфликтов и случаев внешнего контекста.
- TP/FP/FN, precision/recall с знаменателями; отдельно пропуски поиска, неверная классификация, дубли эпизодов и сдвиг времени. Для неизвестных — число ошибочных уверенных выводов и корректных воздержаний. Не исключать failed из отчёта так, будто они успешные отрицательные.
- Ошибки исходных JPEG/PTS, достаточности контекста, границ эпизодов; latency полного пути, включая уточнение и доказательства, отдельно загрузка модели.
- Коммиты A/B/C, модель/revision, конфигурация окон/кадров, версия политики, SHA локального манифеста и frozen split; кто проверил и дата.

Минимум наличие каждого вида случаев требуется для проверки логики, но несколько примеров не доказывают надёжность. Численные пороги качества и допустимый риск команда должна заранее согласовать; сейчас таких утверждённых порогов нет. Ошибочный уверенный вывод на неоднозначности, смешение смены внимания с уходом или отсутствие настоящего положительного случая блокируют активацию до разбора.

## Результат приёмки

Заполнять отдельно: пригодность класса на данных; качество извлечения фактов; качество решения; достаточность доказательств; отрицательная политика; неизвестность по ТЗ; сквозной API. У каждого пункта статус pass/fail/not_run, агрегированные результаты, проверившие участники и ревизии. Сейчас все проверки реальных случаев — not_run. Активация допускается только отдельным решением после необходимых проверок; этот документ её не выполняет.
