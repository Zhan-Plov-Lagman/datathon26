# Запуск координатора C

Координатор не загружает модель и не требует CUDA. Нужен Python 3.12+; локально проверяется на Python 3.13.15. На GPU-ноутбуках использовать среду A из `WORKER.md` (Python 3.12).

**Актуальный выбор пользователя 18 октября:** весь сервис на A, без VPN; публичный адрес позже. Готовая инструкция с сохранением ветки A и повторным использованием её среды/весов — [SINGLE_LAPTOP.md](SINGLE_LAPTOP.md). Команда `start.ps1 -WithWorker -Python <python-A>` запускает supervisor только после настройки настоящей фабрики правил. Текущие блокеры A/B — [INTEGRATION_C.md](INTEGRATION_C.md). Команды распределённого запуска ниже остаются справочными.

## Быстрый старт Windows

Из корня репозитория:

```powershell
.\start.ps1
```

Скрипт создаёт `.venv`, устанавливает закреплённые зависимости, создаёт `.env` с двумя случайными ключами, запускает два процесса. Откройте **http://127.0.0.1:8000**. Введите `FORTE_API_KEY` из локального `.env`. Скрипт не печатает ключи, существующий `.env` сохраняет. Остановка — Ctrl+C.

Если PowerShell запрещает запуск скрипта, используйте отдельные команды:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-api.txt
.\.venv\Scripts\python.exe -m scripts.setup_coordinator
.\.venv\Scripts\python.exe -m app.api
```

После первой установки для повторного запуска достаточно последней команды. Runtime не требует сети или установки пакетов.

`.env` — только локальный файл. `FORTE_API_KEY` нужен браузеру/жюри, `FORTE_WORKER_KEY` — только GPU-ноутбукам. Не передавать их в URL, Git или сообщения помощнику.

SQLite и загруженные видео по умолчанию находятся в `%LOCALAPPDATA%/Datathon26/runtime`; на Linux — `~/.local/share/Datathon26/runtime`. Это отдельный локальный диск, не OneDrive и не общий сетевой каталог. Переопределение — `FORTE_STORAGE` в `.env`. Все два процесса API должны использовать один и тот же каталог. Не запускать две независимые копии координатора с разными базами под одним публичным адресом.

## Подключение первой GPU

На C запустите закрытый сервер на адресе интерфейса общей защищённой сети команды:

```powershell
.\.venv\Scripts\python.exe -m app.api --worker-host <private-IP-C>
```

Публичный сервер остаётся на `127.0.0.1:8000`. На защищённом интерфейсе C разрешите вход на 8001 только адресам A/B. Не открывайте этот порт в интернет. HTTP здесь допустим только внутри уже зашифрованной сети команды; для обычной LAN требуется отдельный TLS/защищённый туннель. Конкретную сеть команда выбирает на месте.

На A после готовности правил B:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-api.txt
# В локальном .env на A: WORKER_KEY, COORDINATOR, MODEL_DIR, RULES_FACTORY.
.\.venv\Scripts\python.exe -m app.jobs.worker --worker-id gpu-a --coordinator http://<private-IP-C>:8001
```

Модель создаётся один раз в дочернем процессе. При зависании процесс завершается извне. После ошибки процесс пересоздаётся. В штатном режиме GPU выполняет одно задание за раз. Клиент не использует системный HTTP-прокси и не следует редиректам. Исходные данные задания и временный JSON удаляются с GPU-ноутбука после передачи; копия на координаторе сохраняется.

Ветка B на момент реализации C не опубликована. Без `FORTE_RULES_FACTORY` обработчик завершает запуск с понятной ошибкой; UI сообщает, что анализ недоступен. Не запускать тестовые фабрики `tests.*` на сервисе жюри. Стык для B описан в [WORKER_TRANSPORT.md](WORKER_TRANSPORT.md).

Второй ноутбук подключается такой же командой с `--worker-id gpu-b`, после полного одиночного прогона с настоящей моделью/правилами. Разные процессы не должны использовать один worker ID.

## Публичный HTTPS

По ТЗ адрес и ключ создаёт команда. `team.example.kz` в ТЗ — пример, не выданный адрес. Нужны домен, доступный извне адрес и перенаправление TCP 80/443 на C либо контролируемый командой защищённый вход в её сеть. При CGNAT обычное перенаправление портов не сработает. Видео и результаты не размещать в стороннем хостинге или облачных AI.

Для прямого входа на C подготовлен `deploy/Caddyfile`. Установите Caddy отдельно, настройте DNS, разрешите 80/443, затем:

```powershell
$env:FORTE_DOMAIN = '<ваш-домен>'
caddy validate --config deploy/Caddyfile --adapter caddyfile
caddy run --config deploy/Caddyfile --adapter caddyfile
```

Caddy получает сертификат и проксирует только UI и публичные методы на 8000. Порт 8001 в конфигурации отсутствует, неизвестные маршруты возвращают 404. Не добавлять access/body logging. Сертификаты требуют внешней сети при выпуске/обновлении; обработка видео внешнюю сеть не использует.

С компьютера **в другой сети**, с ключом в его локальной переменной `FORTE_API_KEY`:

```powershell
python -m scripts.check_api https://<ваш-домен>
```

Скрипт проверяет доступ, 401 без ключа/с неверным ключом, 404 неизвестного задания с верным ключом и недоступность внутренних маршрутов. Он печатает только статусы и не загружает видео. Затем нужен настоящий сквозной MOV через POST/GET с локальной проверкой JPEG, времени и вердикта. Успех health/auth-проверки не подтверждает готовность анализа.

## Поведение и эксплуатация

| Параметр | Значение по умолчанию |
| --- | --- |
| Размер MOV | до 256 МиБ |
| Размер внутреннего JSON | до 32 МиБ |
| Общий срок задания | 240 с от начала HTTP-загрузки |
| Аренда | 30 с, heartbeat каждые 10 с |
| Попытки | максимум 2 |
| Одновременно незавершённые задания | максимум 8 |
| Готовность обработчика | heartbeat не старше 45 с |

Лимит очереди — защита ресурсов, а не обещание обработать восемь одновременных видео за пять минут. Настроить по измеренному времени A/B и фактической нагрузке жюри. Пустая очередь не означает готовность модели. `/api/v1/readiness` требует ключ и возвращает 503 без готовых обработчиков; `/healthz` подтверждает только работу HTTP-процесса.

API может принять задание до подключения обработчика; оно ожидает в очереди до общего дедлайна и затем становится `failed`. UI предварительно проверяет готовность и не начинает такую загрузку. После перезапуска координатора данные сохраняются. После потери обработчика аренда истекает и допускается одна повторная попытка в оставшемся бюджете. Просроченный ответ получает 409. Уже принятый итог не меняется.

При неверном/пустом файле запрос отклоняется; повреждённый MOV, обнаруженный при декодировании на A, завершает задание `failed`. Размер проверяется и по потоку HTTP, и при сохранении файла. Полная проверка декодирования выполняется обработчиком. Прерванное до создания задания сохранение удаляется; аварийное выключение между сохранением файла и INSERT может оставить безвредный файл без задания. Автоматическое удаление исходников/итогов после хакатона не включено: срок хранения согласовать с организаторами.

Браузер воспроизводит выбранный файл локально. После перезагрузки страницы сохраняется только последний job ID; ключ вводится заново, а для переходов по времени нужно снова выбрать соответствующий исходный файл. Поддержка кодека MOV зависит от браузера; кадры JPEG доступны независимо от воспроизведения.

## Ноутбуки в разных сетях, без домена

Текущая схема обходится без связи между ноутбуками: всё запускается на A. Публичный HTTPS отложен пользователем, localhost не заменяет требование ТЗ. Статус сети — [NETWORK_C.md](NETWORK_C.md). Caddy остаётся вариантом при появлении собственного домена и маршрута; новый внешний транспорт пока не настроен.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-test.txt
.\.venv\Scripts\python.exe -m pytest tests/api -q
# С установленным Edge; для Chrome задать FORTE_BROWSER_CHANNEL=chrome.
.\.venv\Scripts\python.exe -m pytest tests/browser -q
.\.venv\Scripts\python.exe -m pip check
node --check web/app.js
```

Браузерные тесты запускают локальный HTTP-сервер и создают синтетический MOV. Снимки — только в `.cache/browser`, вне Git. Для CPU-тестов C не нужны CUDA, Qwen и банковские видео.
