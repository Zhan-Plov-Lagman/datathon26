- `evaluation/`: локальная заготовка разметки с сохранением исходных аннотаций, отметка конфликтов дубликатов, транзитивное объединение хешей/сцен, детерминированное разделение, фиксация SHA манифеста, один представитель дубликатов, оценка видео/событий/типов/локализации/времени и сбоев.
- Инструкции: [стык правил](RULES_B.md), [проверка нормативов](REGULATORY_REVIEW_B.md), [оценка](../evaluation/README.md).

**Остаётся обязательная работа:**

1. Человек команды просматривает видео локально, определяет независимые сцены, проверяет разные таймкоды дубликата и заполняет события. Это требование ROLE_B, а не задача облачного просмотра. До этого `data/splits.json` намеренно не создан: независимость сцен нельзя установить по SHA.
2. A/B согласуют и реализуют локальное извлечение пакетов фактов: нынешний A возвращает описания, не `facts`. Пример нового стыка в RULES_B. Не включать проверенные правовые тексты в автоматический вердикт до проверки распознаваемости класса, исключений и ложных срабатываний.
3. A/C подключают уточнение, назначение идентификаторов эпизодов, исходные JPEG и политику отрицательного результата. Этот модуль не выдаёт `no_violation` по пустым наблюдениям. Семантическую неопределённость не маскировать техническим отказом без согласованной политики.
4. Получить веса и Python 3.12 среду A, объединить код A/C на интеграционной машине, выполнить настоящий baseline, сложные отрицательные, новый ракурс, полный latency и затем настроечные эксперименты по одному фактору. GPU-процесс на B не запущен, модель и её качество на B не проверены.

**Не заявляем:** готовый юридический анализ, завершённую разметку/независимый holdout, измеренную точность, реальный baseline или работу второго GPU-обработчика. Синтетические тесты доказывают логику кода, не качество зрения. Нормативный каталог проверен по тексту, но продуктовые классы не активированы.
