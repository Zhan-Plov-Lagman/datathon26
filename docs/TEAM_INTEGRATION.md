# Как забрать ИТОГ и сохранить свой фронтенд

Актуальный объединённый код находится в ветке `integration/forte-unified` репозитория
https://github.com/Zhan-Plov-Lagman/datathon26.
Исходная проверенная версия реализации — `464d3d6`.
Ветки `main` и `feature/api-ui` автоматически не обновляются при публикации этой ветки.

## Получить код без изменения текущей папки

В терминале **из существующего клона командного репозитория**:

```text
git status --short
git fetch origin
git worktree add -b integration/friend-ui ../datathon26-integration origin/integration/forte-unified
```

Команда создаёт соседнюю папку `datathon26-integration` и отдельную ветку для переноса
фронтенда. Исходная папка, текущая ветка и незакоммиченные изменения остаются на месте.
Если такая папка или ветка уже есть, остановиться и проверить её состояние; не удалять
её и не применять `reset --hard`, `clean` или принудительное переключение.

Открыть новую папку в редакторе. Изменения фронтенда переносить после просмотра diff,
сохраняя API-контракт. Не заменять целиком `app/` старой копией.

## Проверить интерфейс и авторизацию без модели

Из новой папки в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

Скрипт использует установленный Python, при необходимости создаёт `.venv`, устанавливает
зависимости API и создаёт `.env`, если его ещё нет. Существующий `.env` сохраняется.
Затем запускаются публичный API/сайт на `http://127.0.0.1:8000` и закрытый транспорт
на `127.0.0.1:8001`. Перед запуском остановить только свою прежнюю копию сервиса,
если она занимает эти порты. Права администратора для этого не нужны.

Во втором терминале **из той же новой папки**:

```powershell
Select-String -Path .\.env -Pattern '^FORTE_API_KEY='
```

В поле сайта «Ключ доступа» вставить только значение после `FORTE_API_KEY=`.
На этом компьютере это ключ этого API; ключ отдельного сервера Runpod не заменяет его.
Не использовать `FORTE_WORKER_KEY`. `.env` не передаётся через Git.
Если ключ менялся после старта, процесс нужно перезапустить. Переменная окружения
`FORTE_API_KEY`, заданная до старта, имеет приоритет над `.env`.

Проверка API из той же папки:

```powershell
.\.venv\Scripts\python.exe -m scripts.check_api http://127.0.0.1:8000
```

`401` означает отказ авторизации. Правильный ключ и отсутствие готового обработчика
дают `503` на `/api/v1/readiness`; это другая проблема. В этом режиме не заявляется
готовность анализа, модель не скачивается и не заменяется заглушкой.

## Задание ИИ друга для переноса его интерфейса

> Прочитай AGENTS.md, docs/CONTRACTS.md, docs/TEAM_INTEGRATION.md,
> docs/UNIFIED_PIPELINE.md и актуальное начало INTEGRATION_STATUS.md.
> Новый объединённый код опубликован в origin/integration/forte-unified.
> Мой изменённый фронтенд находится в прежней папке проекта.
> Сначала проверь статус обоих рабочих деревьев и сохрани мои изменения.
> Работай в отдельной ветке integration/friend-ui нового worktree.
> Сравни мой фронтенд с новым web/ и перенеси только нужные изменения интерфейса.
> Сохрани POST /api/v1/analyze, GET /api/v1/jobs/{job_id}, X-API-Key и работу
> с настоящими ответами API. Не подставляй выдуманные результаты анализа.
> Проверь авторизацию правильным и неверным локальным ключом, 503 без worker,
> загрузку/опрос на синтетических тестах и показ ошибок. Не публикуй .env,
> видео или модельные ответы. Пришли коммит и результаты проверок.

## Что публикация кода не делает

Она не переносит веса, CUDA-среду, приватные результаты, локальные ключи или данные.
32B/vLLM проверялись на командном L40S; запускать этот профиль на ноутбуке с 6 ГБ
VRAM не следует. Настройка серверного запуска — `docs/RUNPOD_SETUP.md` и
`docs/VLLM_BACKEND.md`; измерения — `docs/BACKEND_COMPARISON.md`.

На момент этой передачи UI/API на Runpod были запущены, но проверка публичного
доступа не прошла, а готовый GPU worker к API не подключён. Полный путь от сайта
до реального итогового анализа и качество распознавания ещё требуют проверки.
Опубликованная ветка содержит реализацию и проверенные отдельные компоненты,
а не подтверждение готовности сервиса для жюри.
