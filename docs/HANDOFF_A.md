# Передача результата роли A

Дата: 17 октября 2026. Участник: Арман, RTX 4050 Laptop 6 ГБ. Ветка: `feature/ml-worker` в https://github.com/Zhan-Plov-Lagman/datathon26.

**Что готово.** Локальное чтение MOV, выбор кадров по реальному PTS, окна с перекрытием, Qwen3-VL-2B-Instruct в NF4, проверка структурированного ответа, уточнение заданного интервала и извлечение 1–3 JPEG исходного разрешения. Модель загружается один раз и переиспользуется между заданиями. Сбой формата, декодирования или дедлайн не превращается в отрицательный вердикт.

**Что проверено.** Все 15 тестов `python -m unittest discover -s tests/worker -v` прошли. Среди них VFR-таймкоды, поворот видео, JPEG, границы интервалов, ошибочные ответы, сохранение смешанных типов весов при разбиении safetensors, общий дедлайн уточнений, однопроходное извлечение доказательств, защита от конкурентного вызова и ограниченный повтор ошибки JSON. `pip check` не выявил несовместимых зависимостей.

Синтетический GPU-прогон: видео 3 секунды, 4 кадра, одно окно; загрузка модели 18,343 с, анализ 4,938 с, включая декодирование 1,094 с. Пиковая выделенная память PyTorch — 1926 МиБ, зарезервированная — 2030 МиБ. Эти величины не включают память других приложений и не доказывают качество на банковских сценах.

Технический прогон двух реальных роликов выбран по длительности, без использования разметки. Настройки: окна 12 с, перекрытие 2 с, 6 кадров на окно, длинная сторона до 560 px, максимум 384 новых токена. Оба ролика обработаны полностью в смысле всех запланированных окон; дополнительно проверено извлечение последнего исходного JPEG.

Модель уже была загружена при старте измерения каждого ролика; в памяти между заданиями сохранялся один экземпляр. Пики памяти накопительные для процесса. Это один прогон, а не p95 и не измерение публичного сервиса: здесь нет очереди, правил B, автоматических уточнений и сетевой выдачи. Точность описаний и нарушений ещё не оценена. Подробные ответы сохранены только локально в `artifacts/benchmark-run1`; облачному помощнику передавались лишь технические метрики.

**Расширенный маршрут A: обзор → уточнение → пакет JPEG.** Проверен `LocalGPUWorker` с одним общим бюджетом 240 с. Для технического замера выбирался восьмисекундный интервал из середины ролика, без чтения меток и без объявления события нарушением.

- Короткий ролик 11,63 с: полный маршрут 31,75 с; уточнение 22,33 с, 3 окна.
- Длинный ролик 142,53 с: полный маршрут 121,58 с; обзор 94,66 с (15 окон), уточнение 24,86 с (3 окна), один повтор JSON. Пики PyTorch за процесс: allocated 2093,2 МиБ, reserved 2154 МиБ.

Первый расширенный прогон длинного ролика остановился на ошибке формата через 106,52 с. После добавления ограниченного повтора повторный полный прогон завершился успешно. Это подтверждает обработку обнаруженного сбоя, но не гарантирует, что произвольный ответ модели всегда удастся восстановить. Повторная ошибка остаётся техническим отказом. Подробные результаты находятся локально в `artifacts/benchmark-worker-refinement-run1` и `artifacts/benchmark-worker-refinement-run2`. Время не включает холодную загрузку модели, очередь, правила B или сетевую выдачу C.

**Воспроизводимость.** Python 3.12.14; torch 2.8.0+cu128; torchvision 0.23.0+cu128; transformers 4.57.6; accelerate 1.12.0; bitsandbytes 0.48.2; av 16.1.0; Pillow 12.1.0. Остальные основные зависимости закреплены в `requirements-worker.txt`. Ревизия Qwen: `89644892e4d85e24eaac8bacfd4f463576704203`. Используются SDPA, float16 вычисления и NF4 с double quantization; дополнительного обучения нет.

На Windows единый файл весов не загрузился из-за error 1455. Рабочий вариант — восемь частей в `models/Qwen3-VL-2B-Instruct-shards`; монолитная копия удалена для освобождения места. Подготовка и запуск описаны в [WORKER.md](WORKER.md). На этой машине повторно скачивать или разбивать модель не требуется. В Git нет весов, среды Python или банковских данных.

**Стык B.** `LocalVideoAnalyzer.analyze` возвращает `observations.v1`, `analysis_kind: observations_only`. Получать `windows`, `operation_context`, наблюдения и ограничения обзора. Времена наблюдений вычислены из индексов кадров. Свободный текст модели — визуальная гипотеза, не доказательство применимости правовой нормы. Нужны проверенные правила, исключения, дедупликация событий и оценка качества на независимых сценах. Описание схемы — `docs/CONTRACTS.md`.

**Стык C.** Создать `QwenObserver` и один `LocalGPUWorker` при старте GPU-процесса. Вызовы: `analyze`, `refine`, `evidence`; все принимают общий локальный monotonic-дедлайн. Занятый обработчик выбрасывает `WorkerBusy`, после любой ошибки освобождает блокировку. Между ноутбуками передавать оставшийся бюджет, а не значение monotonic-часов. Не создавать модель на каждом HTTP-запросе. C формирует публичный контракт только после правил B. Общий бюджет включает очередь, анализ, уточнения и выдачу; кооперативный дедлайн внутри модели не заменяет внешний контроль процесса.

**Уточнение для B.** Передавать список `{candidate_id, start_sec, end_sec}` в `worker.refine`; получать `refinements.v1` со списком `{candidate_id, report}`. Окна уточнения — 4 с / перекрытие 1 с / 6 кадров; одинаковые интервалы переиспользуют один результат. Весь список имеет один бюджет. Ответ не подтверждает применимость нормы: B повторно проверяет наблюдения, выбирает опорные времена и только затем C запрашивает `worker.evidence(video_path, {candidate_id: [time1, time2]}, deadline=...)`. Все доказательства извлекаются за один проход видео. Точные сигнатуры и пример — [WORKER.md](WORKER.md).

**Ошибки формата.** При синтаксически неверном JSON разрешён один повтор с более кратким форматом ответа и тем же дедлайном. Повтор содержит те же кадры, не использует метки и не подставляет пустые наблюдения. Ошибка схемы, в том числе неверный индекс кадра, остаётся ошибкой без автоматического исправления. В окне добавлена техническая метрика `generation.attempts`, а в GPU-метриках — накопительный `format_retries`. Сырые ответы модели не выводятся в диагностику.

**Что ещё требуется.** B подключает выбор кандидатов и нормативный вердикт, C — транспорт задач, API и очередь. Их реализация не дублируется в этой ветке. Пустые наблюдения не означают `no_violation`. Редкая обзорная выборка может пропустить быстрые действия. Нужны человеческая оценка качества, согласование B/C и сквозной прогон публичного сервиса.

**Ближайшие действия команды.** B начинает `prompts/ROLE_B.md`; C — `prompts/ROLE_C.md`. Оба читают этот документ и `docs/WORKER.md` из ветки A. C получает ветку командой `git fetch origin` и объединяет её после проверки интерфейсов. A продолжает локальные измерения и помогает уточнять события, не дублируя работу B/C.
