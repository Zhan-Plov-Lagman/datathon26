# Подключение правил B

Python 3.12+; внешних зависимостей нет. Проверено на Python 3.14.3. Общие зависимости C и код A не изменяются. `config/rules.yaml` записан в JSON-синтаксисе, являющемся подмножеством YAML 1.2; загрузчик читает именно этот синтаксис стандартным `json`.

```python
from app.rules import evaluate

result = evaluate(observations_report, local_assessments)
for event in result['supported']:
    # A извлекает исходные JPEG по event['anchor_sec'].
    # C проверяет кадры и сериализует обязательные поля API.
    pass
```

`observations_report` — реальный `observations.v1` из ветки A: `video.duration_sec`, `complete`, `coverage_scope`, `windows[].window_id`, реальные времена кадров и наблюдений. Свободные `description` и `operation_context` не разбираются по ключевым словам и не считаются юридическими фактами.

`local_assessments` — **новый предлагаемый стык**, требующий реализации/согласования с A, а не уже существующий выход Qwen. Сначала формируется локально человеком или проверенным локальным извлекателем фактов, затем уточняется. Нельзя подставлять в него организаторские метки. Один пакет на один эпизод и правило:

```json
{
  "rule_id": "cashier_leaves_service",
  "event_id": "synthetic-operation-1-episode-1",
  "observation_refs": [{"window_id": 0, "observation_index": 0}],
  "anchor_sec": 2,
  "facts": {
    "bank_cash_acceptance": true,
    "actor_is_cashier": true,
    "cashier_left_workplace": true,
    "service_in_progress": true,
    "service_completed": false
  },
  "refinement_complete": true,
  "full_sequence_visible": true
}
```

Это синтетический пример формы, не аннотация данных. Вход CLI — массив таких объектов. Отсутствующее поле факта / `null` означает неизвестность; исключение требуется явно проверить как `false`. Значение `"false"` строкой не принимается. `event_id` назначает локальный трекер эпизодов; соседние окна одного эпизода должны быть сведены в один пакет со всеми ссылками. Повтор `(rule_id, event_id)` отклоняется: не объединяем противоречивые пакеты и разные эпизоды по близости времени.

`anchor_sec` обязан совпасть с реальным временем кадра внутри одного из наблюдений. Для бездействия выбирать окончание этапа, к которому действие должно было произойти, с полным контекстом до/после. Список ограничений видимости блокирует подтверждение: передать уточняющий отчёт без этого ограничения, а не просто удалить его из старого отчёта. `full_sequence_visible` не выводится из `complete`: обработанные редкие кадры не гарантируют видимость всей операции.

Выход содержит `candidate`, `supported`, `rejected`, проверенные условия, исключения, причины, ссылки, версию и SHA-256 реестра, метаданные модели. Шаблон объяснения и реквизиты берутся только из реестра. `supported` означает готовность к извлечению/проверке доказательств, а не готовый ответ API. Доказательства и конкретное наблюдаемое действие A/C добавляют локально.

Все пять классов пока `hypothesis`: текст источника проверен, но пригодность классов по данным не подтверждена. В `reviewed` переводить только после локальных положительных и трудных отрицательных проверок, фиксации ревьюера и `validated_on_local_cases: true`. Название статуса относится к готовности **продуктового правила**, а `source.text_verified` — отдельно к прочитанному нормативному тексту.

Пустой список пакетов сам по себе не обосновывает `no_violation`; обзор `interval` не заменяет полный технический проход. По поправке C 2628639 добавлена отдельная `finalize_detection` — [DECISION_CONTRACT_B.md](DECISION_CONTRACT_B.md): после выполненных детекторов отсутствие обоснованных событий даёт «признаки не обнаружены», даже если остались кандидаты с неизвестными фактами. Факты не заменяются false. Нужна квитанция фактического выполнения каждого настроенного детектора; активный проверенный охват и происхождение квитанции проверяются отдельно. `public_verdict_ready` остаётся false до интеграции/валидации; C собирает evidence и публичный ответ. Ошибку входа/неполный технический проход не выдавать за отрицательный результат; ошибку конфигурации выявлять до приёма задач. Противоречие двух true о продолжении и завершении обслуживания финализатор сохраняет в unresolved, не подтверждает событие и не представляет как обычное отклонение.
